# Korean-first slide copy

한국어 발표 자료의 제목·본문·라벨을 영어 템플릿 번역처럼 쓰지 않기 위한 편집 규칙이다.

시각 스타일이나 도메인과 무관하게 **관객이 한 번에 읽고 이해하는 한국어**를 우선한다. 스포츠, 강의, 제품 보고서처럼 특정 분야에서만 쓰는 어휘는 해당 템플릿 문서에 둔다.

1. 기본 원칙
2. 영어를 남겨도 되는 경우
3. 번역체를 만드는 패턴

5. 표·지표·UI 라벨

7. 최종 편집 점검

## 1. 기본 원칙

- 한국어 덱은 한국어로 먼저 문장을 만든다.
- 영어 원문을 그대로 놓고 단어별로 번역하지 않는다.
- 제목은 장면의 결론이나 역할을 먼저 말한다. 설명은 본문으로 내린다.
- 명사만 길게 쌓기보다 주어·상태·변화가 드러나는 짧은 구를 쓴다.
- 짧게 만든다는 이유로 조사와 핵심 관계를 지워 뜻이 모호해지지 않게 한다.
- 디자인을 먼저 고정한 뒤 카피를 억지로 끼워 넣지 않는다. 실제 한국어 줄 길이로 레이아웃을 잡는다.
- 한국어 노출 문구에서는 가운뎃점 `·`, en dash `–`, em dash `—`를 쓰지 않는다. 관계는 조사, 쉼표, 줄바꿈, 괄호로 풀고 숫자 범위는 `3~8월`, `3.75~4.00%`처럼 쓴다.
- `data-copy-en-ok`로 영어 예외를 허용해도 위 기호 금지는 그대로 적용한다.
- 도메인 특유의 어휘는 코어 카피 규칙에 섞지 않고 해당 템플릿 가이드에서 다룬다.

## 2. 영어를 남겨도 되는 경우

영어가 관객의 읽는 속도를 실제로 높일 때 유지할 수 있다.

- 널리 쓰이는 약어: `AI`, `API`, `UI`, `UX`, `HTML`
- 공식 브랜드·제품명
- 기술 표준이나 프로토콜명
- 원문 인용
- 출처·메타데이터

영어가 단지 더 전문적으로 보인다는 이유는 유지 근거가 아니다.

의도적으로 유지한 노출 문구는 해당 요소나 부모에 `data-copy-en-ok`를 붙인다.
이 표시는 검토가 끝난 예외 한 곳을 뜻하며, 슬라이드 전체 면제 용도가 아니다.

## 3. 번역체를 만드는 패턴

### 추상 동사로 끝내기

피한다:

- `이번 결과가 새로운 시그널을 보여준다`
- `이 데이터가 업무 변화를 설명한다`
- `다음 단계에서 전략을 재검증한다`

바꾼다:

- `핵심 변화`
- `업무 흐름에서 달라진 점`
- `다음 검증 단계`

### 영어 명사 덩어리의 어순 보존

피한다:

- `워크플로 인사이트 리포트`
- `프로젝트 넥스트 스텝`
- `키 테이크어웨이 정리`

바꾼다:

- `업무 흐름 분석`
- `다음 단계`
- `핵심 정리`

### 같은 의미를 이중으로 말하기

피한다:

- `현재 시점에서 지금의 상태`
- `핵심 포인트 요약 정리`
- `향후 다음 단계 계획`

바꾼다:

- `현재 상태`
- `핵심 정리`
- `다음 단계`

## 4. 제목과 소제목

제목은 1초 안에 장면의 역할이 보이게 쓴다.

좋은 방향:

- `프론트엔드 생성의 자동화`
- `반복되는 시각 문법`
- `문제는 장식보다 판단의 부재다`
- `전과 후를 같은 기준으로 비교`
- `다음 단계`

피할 방향:

- `KEY TAKEAWAYS`
- `NEXT STEPS`
- `OVERVIEW`
- `새로운 변화가 시작되는 순간을 설명하다`

소제목은 제목을 다시 말하지 말고 근거·맥락·조건을 보탠다.

예:

```text
문제는 장식보다 판단의 부재다
우선순위, 제약, 상태가 정해지지 않은 화면
```

## 5. 표·지표·UI 라벨

한글이 더 빨리 읽히는 일반 라벨은 한글로 쓴다.

| 영어 템플릿 | 한국어 권장 |
|---|---|
| OVERVIEW | 개요 |
| KEY TAKEAWAYS | 핵심 정리 |
| NEXT STEPS | 다음 단계 |
| STATUS | 상태 |
| RESULTS | 결과 |
| COMPARISON | 비교 |
| SUMMARY | 요약 |
| INSIGHTS | 분석 결과 |

공간이 매우 좁고 해당 분야에서 널리 쓰이는 약어는 유지할 수 있다.
다만 일반 관객이나 학생 대상이라면 가능한 한 풀어 쓰는 편이 낫다.

## 6. 전/후 예시

### 강의 자료

Before:

```text
KEY TAKEAWAYS
What this means for our workflow
```

After:

```text
핵심 정리
업무 흐름에서 달라지는 점
```

### 프로젝트 보고

Before:

```text
PROJECT STATUS OVERVIEW
NEXT ACTION ITEMS
```

After:

```text
프로젝트 현재 상태
다음 할 일
```

### 비교 장면

Before:

```text
BEFORE / AFTER
VISUAL IMPROVEMENT
```

After:

```text
이전 / 개선 후
달라진 점
```

## 7. 최종 편집 점검

- 제목만 훑어도 덱의 흐름이 한국어로 자연스럽게 이어지는가?
- 영어를 지웠을 때 정보 손실이 없는 일반 라벨이 남아 있지 않은가?
- 영어를 남긴 각 항목에 약어·브랜드·인용 등 분명한 이유가 있는가?
- 한글 제목이 영문 원문의 어순을 그대로 따라가지 않는가?
- `~을 설명한다`, `~을 보여준다`, `~을 재검증한다` 같은 추상 동사를 더 직접적인 표현으로 바꿀 수 있는가?
- 같은 의미를 두 번 말하는 단어가 겹치지 않는가?
- 줄바꿈이 디자인 균형이 아니라 의미 단위에 맞춰져 있는가?
- 가운뎃점 `·`, en dash `–`, em dash `—`가 남아 있지 않은가?
- 숫자 범위가 긴 대시 대신 물결표 `~`로 적혀 있는가?
- 특정 도메인 어휘가 코어 문서에 불필요하게 섞이지 않았는가?
- `python tools/copy_lint.py deck.html --strict`가 통과하는가?

카피 린트 통과는 자연스러운 문장이라는 인증이 아니다. 마지막 품질 판정은 위 질문을 이용한 편집 검토다.
